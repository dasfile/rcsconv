# Roadmap

Статус: Python-реализация закрыта по приёмке (версия 1.0.0, см. `PLAN.md`).
Дальнейшие шаги — по приоритету владельца.

## 1. Rust-порт (следующий крупный шаг)

Цель — скорость и мультипоточность: сейчас Python даёт ~27 тыс. точек/с на `.pts`
и 19 с на 324 680 точек `.laz`.

- **Тулчейн: GNU** (`stable-x86_64-pc-windows-gnu`) поверх установленного WinLibs
  (gcc 16.2, UCRT). **MSVC не используется** — решение владельца.
- Сначала владельцу нужно поставить `rustup` и убедиться, что `cargo build`
  работает с GNU-таргетом.
- Структура (план): `rust/` — workspace; crates `rcs-format` (заголовок, блоки,
  тела точек), `rcs-cloud` (октодерево), `rcs-read`, `cloud-pts`, `cloud-las`,
  `rcsconv-cli`.
- Приёмка: **побайтовый паритет с Python** на всех эталонах (`probe6/test1/test2`,
  `level_7`), затем цели по скорости (≥1 млн точек/с на `.pts`).
- Python остаётся эталонной реализацией и «оракулом» для паритетных тестов.

## 2. Плагин Revit (C#) — ждём материалы владельца

Задача: вставлять `.laz`/`.e57` напрямую в модель Revit. У владельца есть
наработки — после их передачи появится отдельный документ с архитектурой
(что вызывает конвертер, как кэшировать `.rcs`, как вести себя при обновлении).

Пока **не начат**: без материалов нельзя выбрать ни API (Revit API vs внешний
процесс), ни формат поставки (add-in + CLI).

## 3. `.e57` — отложено

Причина — нет корректного `.e57`: и файлы libe57.org, и экспорт CloudCompare
2.14.beta содержат повреждённый XML (детали — `docs/CORPUS.md`). Практический
путь сейчас: `e57 → CloudCompare → .laz → tools/las2rcs.py`.
Когда появится читаемый файл: `e57_read.py` + `e572rcs.py` (см. `PLAN.md`, F2).

## 4. Backlog §12 по формату `.rcs`

Порядок по ценности (все — «на понимание», на совместимость не влияют):

1. механизм децимации при экспорте Unified (сетка ≈5 мм);
2. байты тела `[12]`/`[13]`;
3. поля записи узла `@96/@112/@116/@120/tail`;
4. записи `kind 0…7` в заголовке payload'а;
5. `count` заголовка против суммы по узлам.
